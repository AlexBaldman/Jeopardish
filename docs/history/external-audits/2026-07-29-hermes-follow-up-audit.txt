What improved / looks good
1. Tests/lint are now genuinely green
This is not a “totally broken branch” anymore. The current local branch has a respectable baseline: 72 tests, JS lint, CSS lint all passing.

2. Boot architecture is cleaner
src/main.js has been reduced to a bootstrap file. Service init, preferences, UI bindings, and console conductor are split into src/init/*. This is a good direction and matches the “Carmack Rule” better than the older giant main file.

3. Audio no longer appears to block boot
src/init/services.js:24–31 starts soundManager.init() without awaiting it. That aligns with the previous P0 recommendation.

4. Question service is more defensive
src/services/api/questionService.js now has explicit data content-type recognition and HTML fallback detection. Tests cover rejecting HTML fallback pretending to be TSV/CSV in tests/services/questionService.test.js:92–99.

That is exactly the kind of production hardening this project needed.

5. Answer validation tests are stronger
tests/core/validation.test.js and src/utils/validators.js now cover prompt-prefix cleanup, alternate answers, parentheticals, fuzzy matching, and explanations. This is moving toward the right “answer judge with reasons” product model.

6. UI/accessibility improved in spots
The new index.html adds:

semantic header
scoreboard region
better button labels
actual input/footer structure
modal close button
keyboard-focusable host click zones
Not finished, but definitely better than inert div soup.

Still-real blockers / risks
P0: Reveal scoring is still not wired into the engine
This remains the biggest correctness bug.

Evidence:

UI emits reveal: src/init/ui.js:594–598
Engine scoring still hardcodes peekUsed: false: src/core/GameEngine.js:376–386
Engine event handlers do not consume game:answer:revealed: src/core/GameEngine.js:592–603
The scoring module supports peek/no-credit, but the active engine does not pass reveal state into it.

So the current branch likely still allows:

reveal answer → type answer → receive normal score

That is the top fix.

P0/P1: Browser secret ingestion still exists
src/init/services.js:42–88 still reads these URL params:

gemini_key
claude_key
key
and stores them in localStorage at src/init/services.js:53–59.

This is still a public-production security problem.

P1: Unsafe innerHTML remains on data-bearing paths
Some newer rendering is safe, but mixed rendering remains.

Important instances:

src/main.js:57 fatal error HTML includes error.message
src/init/services.js:105–110 writes answer via innerHTML
src/init/ui.js:154–160 also writes answer via innerHTML
src/services/DialogManager.js has several message/question/answer innerHTML paths
Controlled template innerHTML is less alarming, but data/archive/user/AI output should use textContent or safe DOM builders.

P1: Fullboard/run modes are still not real game modes
From src/init/ui.js:514–568:

board cell click opens a clue preview modal
run-category increments a progress bar / opacity
These modes smoke-test as visible UI, but they are still not routed through the canonical engine answer/scoring/review flow. They should either be labeled beta/preview or integrated properly.

P1: The GameEngine still runs a perpetual frame loop
src/core/GameEngine.js:124–165 still starts requestAnimationFrame(this.gameLoop) and tracks FPS. The update loop now does less work, which is good, but for a mostly event-driven trivia app this remains unnecessary complexity and battery/CPU waste.

Not a ship-stopper, but worth simplifying after truth/scoring/security.

P1: Dependency risk remains
npm audit --omit=dev still reports the 6 vulnerabilities. The source search suggests the production deps may not be used directly in src/. If true, deleting unused deps may collapse most of the audit surface.

P1: No license file
LICENSE still not present. The README/package can imply licensing, but there is no actual grant.

P1: Build/deploy CI still incomplete
Current CI runs lint/test/build and a permissive axe command, but it does not run the preview runtime smoke as a deployment gate. Since the historical problems were production-preview/runtime problems, CI should eventually run:

npm run build
npm run preview -- --host 127.0.0.1 --port 4174
BASE_URL=http://127.0.0.1:4174 npm run test:runtime
I did not run that now to avoid modifying generated artifacts/screenshots.
